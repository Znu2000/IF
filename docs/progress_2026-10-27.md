Oct 27, 2026 · @이진우

## 피처 선정

위치 피처 7개(`lon_c`, `lat_c`, `home_lon`, `home_lat`, `home_port_km`, `fishing_lon`, `fishing_lat`)를 넣느냐에 따라 두 풀을 따로 만들고 항상 함께 보고합니다.

| 풀 | 목적 | 후보 | 선정 결과 |
| --- | --- | --- | --- |
| Pool A (위치 제외) | 처음 보는 해역의 배에도 통하는 순수 행동 모델 | 339 | 중복 제거 후 250개 전부 |
| Pool B (위치 포함) | 대회 점수 극대화 | 346 | 상위 30개 |

선정은 전부 각 fold의 학습 데이터 안에서만 했습니다 (검증 선박 정보 누수 없음).

1. **사전 필터**: 결측 60% 초과·상수 피처 제거
2. **중요도 3종 통합**: SHAP 40% + 순열 중요도 40% + 상호정보량(MI) 20%의 순위 평균. 한 지표의 편향을 상쇄하려고 섞음
3. **노이즈 검정**: 값을 무작위로 섞은 가짜 피처와 비교 (Boruta 방식)
4. **중복 제거**: Spearman |ρ| ≥ 0.95인 쌍은 상위 하나만 (346 → 약 255)
5. **k 결정**: k를 5\~150·전체로 바꿔 가며 평가해, 최고점 − 1 표준오차 안에 드는 가장 작은 k (1-SE rule)

Pool B는 k=30(0.530)이 최고점(k=150, 0.533)과 차이가 없어 30개를 썼습니다. Pool A는 줄일수록 떨어져(k=60 0.447 < 전체 0.461) 전부 썼습니다. 위치가 빠지면 약한 신호가 여러 피처에 퍼져 있다는 뜻입니다.

**상위 피처**

- Pool B: `area_range_km`(조업 해역 넓이), `cross_day_revisit`(여러 날 같은 어장 재방문), `mv_n_stop_move_switch_median`(정지↔이동 전환), `lat_c`, `longest_streak_std`(최장 연속 이동), `daytype_2_share`(출어일 유형)
- Pool A: `fh_pca_elong_q90`(직선 투망 형상), `longest_streak_mean`, `season_m5/m1_share`(계절), `revisit_cell_ratio_mean`(하루 내 재방문)
- 주의: fold마다 순위가 흔들려 5개 fold 공통 상위 피처는 3\~5개뿐입니다. 엑셀의 '선정빈도'가 높을수록 안정적입니다.

## 분류 모델

기준 모델 1개, 비교군 3개, SOTA 1개, 가설 기반 1개, 앙상블을 같은 fold·같은 피처로 비교했습니다. 성능은 위 차트에 있습니다.

| 모델 | 역할 | 원리 | 넣은 이유 |
| --- | --- | --- | --- |
| M0 Logistic Regression | 기준 | 피처의 선형 결합 (분위수 정규화 후) | 비선형 모델이 얼마나 더 버는지 재는 바닥선 |
| M1 Random Forest | 비교군 | 무작위 트리 600개 투표 | 튜닝 없이 안정적인 고전 모델 |
| M2 LightGBM + Optuna | 비교군 | 트리를 순차로 쌓는 부스팅. fold 내부에서만 튜닝 | 테이블 데이터 표준 |
| M3 CatBoost | 비교군 | 대칭 트리 부스팅, 클래스 가중 √(balanced) | GBDT 다른 구현. **단일 모델 최고** |
| M4 TabM | SOTA | MLP 32개를 가중치 공유로 한 번에 학습 + 수치 구간 임베딩 (ICLR 2025) | 딥러닝 테이블 모델 최신 상위권. 사전학습 가중치 없음 |
| M5 가설 2단계 | 가설 | 4클래스 분류 후, 자망 vs 연안복합 전문 분류기(가설 피처 30개 추가)로 두 클래스 확률 재분배 | 가장 헷갈리는 쌍을 따로 푼다는 가설 |
| M6 앙상블 | 최종 후보 | M2\~M5 확률 평균 | 서로 다른 모델의 오류 상쇄 |

- **클래스 보정(+adj)**: 클래스별 확률 가중치를 다른 fold의 예측과 정답으로만 맞춰 적용 (해당 fold 정답 미사용).
- **TabPFN**: 사전학습 모델이라 Hugging Face 로그인·라이선스 동의가 필요해 코드에 옵션(`--tabpfn`)으로만 넣어 둠.
- **TabM Pool A**: CPU로 2시간 이상 걸려 GPU 서버용(`run_server_tabm.sh`)으로 분리, 아직 미실행.

## MIL 실험

MIL(다중 인스턴스 학습)은 점수 천장을 올리지 못했지만, 천장의 원인과 테스트 대비책을 하나씩 확인해 줬습니다. 선박 1척을 출어일 묶음(하루 피처 93\~101개)으로 보고, attention이 정보 있는 날에 가중치를 주게 했습니다. 동기는 "선박 평균이 업종 신호를 희석시킨다"는 가설의 검증입니다.

- **attention은 의도대로 작동**: 이동일 가중 1.24배, 비이동일 0.08배. attention 상위 3일의 95%가 이동일이고 표류·조업 시간이 평소의 2배입니다.
- **그런데 점수는 같음**: 단독 A 0.489 / B 0.511, CatBoost와 결합해도 B 0.545로 기존 0.540과 차이가 fold 편차(±0.015) 안입니다. → 희석은 주된 병목이 아닙니다.
- **기간이 짧아도 강함**: 배마다 7일만 줘도 A 0.476 / B 0.497 (전체 기간 대비 −0.013). Test A가 짧은 기간으로 나오면 대비책이 됩니다.
- 한계: MIL도 하루 요약 피처를 입력으로 썼습니다. 원시 항적(이미지·시퀀스)을 직접 학습하는 방법은 아직 검증 전입니다.

## 확인된 사실과 한계

많이 올린 것은 튜닝이 아니라 클래스 가중과 행동 피처였고, 구조를 바꾼 시도는 대부분 이득이 없었습니다.

| 시도 | 결과 | 효과 |
| --- | --- | --- |
| CatBoost 클래스 가중 Balanced → √(balanced) | Pool B 0.456 → 0.531 | 큼 |
| 클래스 보정(+adj) | Pool A +0.04\~0.06, Pool B 거의 0 | 위치 제외 시 큼 |
| 가설 피처 (재방문·직선 투망·하루 리듬) | 상위 피처의 66% | 있음 |
| 가설 2단계 구조 (자망↔연안복합 전문가) | 1단계 단독 대비 A +0.002, B −0.004 | 없음 |
| Optuna 튜닝 | B 0.526 < 기본값 0.538 | 없음 |
| MIL (출어일 attention) | GBDT와 동등 | 없음 (기간 강건성은 있음) |

**천장(약 0.54)의 원인** — 구조가 다른 모델들이 모두 0.51\~0.54에 수렴하므로 모델 용량이 아니라 정보량 문제입니다.

1. **라벨 혼합**: fishing\_code는 실제 어구가 아니라 허가 종류. 연안복합은 문어단지·주낙 등 자망·통발과 똑같이 움직이는 어구를 포함합니다.
2. **해상도 부족**: 점별 시각 없음. 1시간 변위 중앙값 11\~12m가 GPS 지터 5\~10m와 같은 크기입니다.
3. **업종 차이가 작음**: 조업 속도 중앙값 연안복합 1.29 / 자망 1.39 / 통발 1.44kn, 하루 이동 4.4\~5.4km로 거의 같고, 채낚기(50.9km)만 확연히 다릅니다.

| 순위 | 추가할 피처 | 노리는 문제 | 비용 |

## 이상탐지(과제 2) 계획

목표는 사고를 미리 예측하는 것이 아니라 **사고 직후 패턴 붕괴를 빠르고 정확하게 감지**하는 것입니다. Test B는 시간대별 항적에 0\~1 이상도를 내고, 실제 사고시각 기준으로 정확성과 조기성을 평가받습니다.

**지금 가진 것**

- 사고 167건 중 69건을 항적과 매칭 (사고 지점 3km, ±1시간). 평가용 세트 `anomaly_eval_set` 30,647행 (사고 시점 189 / 사고 전 460 / 정상 29,998)
- 사고의 50%(84건)가 기관·추진계 고장 → 바다 위 정지·표류·귀항 지연이 핵심 신호 후보
- EDA 기준선: 전역 IsolationForest AUC 사고 시점 0.628, 사고 전 0.496 (사전 예측은 거의 불가)
- 과제 1에서 만든 1시간 피처 92개와 시간대 상태(정박/표류/조업/항해)를 그대로 재사용

**단계별 접근** (앞 단계가 다음 단계의 비교 기준)

1. **평가 설계**: 사고 단위로 분할(같은 사고가 학습·검증에 동시에 들어가지 않게). 지표는 PR-AUC, 사고별 탐지 지연(첫 경보 시각 − 사고 시각), 정상 시간대 오경보율. 69건뿐이라 부트스트랩 신뢰구간 필수
2. **베이스라인**: 전역 IsolationForest 재현 (기준 0.628)
3. **업종별 정상 분포**: 같은 조업형태의 평소 시간대 분포 대비 편차. 테스트에서는 과제 1 분류기가 예측한 업종을 사용 (두 과제 연결)
4. **선박별 평소 기준**: 같은 배의 과거 — 비슷한 시각·같은 상태 — 대비 robust z-score(중앙값·MAD)·마할라노비스 거리. 기록이 적은 배는 업종 기준으로 대체
5. **시간 맥락**: 직전 3·6·12시간 대비 변화량, 상태 전이 이상(조업 중 긴 해상 정지·표류, 평소 귀항 시각 미귀항), 평소 어장 이탈(격자 방문 이력 대비)
6. **시퀀스 모델**: 다음 시간 피처 예측 또는 오토인코더(LSTM/Transformer), 예측 오차 = 이상도. GPU 서버
7. **점수 결합·설명**: 여러 점수를 순위 평균해 0\~1로 변환. 사고 69건으로는 가중치만 가벼게 조정. 점수마다 기여한 피처를 표시(발표 우수성 50점에 중요)

**주의**: GPS 튐이 오경보를 만들 수 있어, 정제 피처와 품질 피처(spike\_ratio 등)를 함께 쓰는 구성 C안을 적용합니다. Test B의 실제 형식은 아직 모릅니다.
