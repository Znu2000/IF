## 1. EDA와 전처리

EDA에서 얻은 핵심은 세 가지입니다. 시간의 절반이 항구 안이고, GPS 지터가 커서 1분 단위 값은 믿을 수 없고, 위치가 업종을 강하게 예측합니다. 전처리는 이 세 가지에 대응하도록 설계했습니다.

### 1.1 데이터 구조

- 원본 1행 = 선박 · 날짜 · 시각(1시간)의 항적(WKT MULTILINESTRING, 약 1분 간격 점). 점별 시각은 없어서 1시간 안에 균등 간격이라고 가정했습니다.
- 학습: 2026년 1\~6월, 7,372척, 원본 약 5.9GB, 시간 행 388만 개.
- 테스트: 2025년 1\~6월 항적. 현재 Test A 100척은 모두 학습에 없는 배이고, Test B 100척 중 10척은 학습에도 있는 ID입니다(연결해 쓰지 않음).
- 라벨(업종)은 선박마다 1개 → 분류 단위는 "선박"입니다.

### 1.3 전처리 규칙 (`fe_hourly.py`, `fe_config.py`)

모든 규칙은 라벨과 무관하게 정했습니다. 테스트에는 라벨이 없으니 같은 규칙을 그대로 재현할 수 있어야 하기 때문입니다.

| 단계 | 규칙 | 왜? |
| --- | --- | --- |
| 튐 제거 | A→B→A에서 A-B가 100m 초과인데 A-C가 왕복 거리의 25% 미만이면 B 제거, 2회 반복 | 한 점만 튀었다 돌아오는 것은 물리적으로 불가능한 GPS 오류. 거리·속도를 크게 부풀림 |
| 평활 | 1시간을 6구간(약 10분)으로 나눠 구간 중앙값 위치로 경로 재구성 | 평균이 아니라 중앙값이라 남은 튀에도 강함. 10분은 지터는 지우고 조업 동작은 남기는 크기 |
| 불가능 이동 | 점 간 15km 초과, 10분 구간 간 7km 초과(약 22노트)는 거리에서 제외 | 어선이 낼 수 없는 속도. 기록 단절 후 점프를 이동으로 세지 않기 위함 |
| 지터 강건 속도·방향 | 5점(약 5분) 간격 step으로 속도·회전 계산, 중앙값·분위수로 요약 | 1분 step은 지터 크기와 이동 거리가 비슷해 정박 중인 배도 움직이는 것처럼 보임 |
| 체류점 | 반경 30m(지터 σ≈10m의 3σ) 안에 3점(약 3분) 이상 머문 곳 | "속도 < 임계값"보다 지터에 강한 정지 판정. 통발 투하 지점 같은 작업 지점을 잡음 |
| 정박 | 평활 경로의 범위가 100m 미만인 시간 | 정박 시간에는 방향·회전 피처가 무의미하므로 0/빈값 처리 |
| 공용 항구 | 정박 시간 위치를 500m 격자로 모아 10척 이상이 정박한 칸 | 항구 위치 자료가 없어 데이터에서 추정. 여러 척이 쓰는 곳만 항구로 본다 |
| 모항 | 배마다 정박이 가장 많이 몰린 1km 격자, 그 2km 안 정지 = 항구 정박 | 작은 항구는 10척 기준에 안 걸리므로 배별 모항으로 보완 |

**테스트 데이터에는 학습에서 만든 항구 격자와 출어일 유형 모델을 고정해서 씁니다.** 테스트로 다시 만들면 같은 피처가 학습과 다른 기준으로 계산되어, 모델이 배운 값의 의미가 바뀝니다.

### 1.4 시간별 상태 판정 (`fe_aggregate.py`)

매 시간을 아래 순서로 판정해 5개 상태 중 하나를 붙입니다. 속도 v는 5분 간격 속도의 중앙값(노트), R은 방향 일관성(0\~1)입니다.

1. **항구(PORT)**: 정박이고 모항 2km 안이거나 공용 항구 0.5km 안
2. **해상 정지(SEA\_STOP)**: 정박이거나 v < 0.3
3. **표류(DRIFT)**: v < 2
4. **조업(FISH)**: v < 5
5. **이동(TRANSIT)**: v ≥ 5이고 R ≥ 0.8 (빠르고 똑바로 감). v ≥ 5여도 방향이 제멋대로면 조업으로 봄

왜 이렇게 나눴나: 업종의 차이는 "바다에서 시간을 어떻게 쓰나"에서 나옵니다. 자망은 그물을 펴고 걷는 동안 저속·정지가 많고, 채낚기는 밤에 표류하며, 연안복합은 배를 직접 조작하며 자주 방향을 바꿉니다. 상태를 먼저 붙이면 이 차이를 상태별 비율·전이·지속 시간 같은 해석 가능한 피처로 바꿀 수 있습니다.

## 2. 피처

현재 모델은 피처 449개를 씁니다. 선박 단위 피처 413개 전체, 지역 사전확률 10개, 재방문 간격 12개, 출어 주기 14개입니다. 2.3\~2.4절의 상위 50개 선정은 이전 모델 `r4_rp`의 방식이고, 전체를 써도 성능이 떨어지지 않아 지금은 고르지 않습니다(7절).

### 2.1 3단계 계층 집계 (`fe_hourly.py` → `fe_aggregate.py`)

| 단계 | 규모 | 담긴 것 |
| --- | --- | --- |
| L1 시간 | 388만 행 × 약 100개 | 그 1시간의 범위·모양·거리·속도·회전·정지·품질 + 상태 |
| L2 선박-일 | 39.9만 행 × 104개 | 그날의 활동량, 항차, 출항·귀항 시각, 상태 전이, 이동 시간대 행동(mv\_\*), 재방문 |
| L3 선박 | 7,372척 × 413개 | 출어일 통계(mean/median/std/p90), 조업 시간 풀링 분위수(fh\_\*), 어장 반복, 계절, 출어일 유형, 위치 7개 |

왜 3단계인가: 라벨은 선박에 붙지만, 업종의 흔적은 "어떤 날"의 "어떤 시간"에 남습니다. 선박 전체를 바로 평균하면 정박일과 조업일이 섞여 희석되므로, 하루 단위로 먼저 요약하고 출어일만 모아 평균·편차를 냅니다. `_std`는 "날마다 얼마나 다르게 일하나"입니다. 연안복합처럼 여러 어구를 번갈아 쓰는 업종을 잡기 위한 것입니다.

이름 규칙: `mv_` = 이동 시간대 행동의 선박-일 값, `fh_` = 조업 시간들을 모아 낸 분위수(q50/q90), `_mean/_median/_std` = 출어일들에 대한 통계, `ks_` = 5분 간격(지터 강건) 계산.

### 2.3 피처 랭킹 (`rank_features.py`)

모든 단계는 **각 fold의 학습 선박으로만** 계산했습니다. 검증 선박을 보고 피처를 고르면 검증 점수가 난관적으로 부풀려 보이기 때문입니다(선정 누수).

| 단계 | 방법 | 왜? |
| --- | --- | --- |
| ① 점수 3종 | SHAP 평균 절댓값 0.4 + 순열 중요도 0.4 + 상호정보량(MI) 0.2의 **순위** 가중합 | SHAP은 모델이 얼마나 썼나, 순열은 빼면 얼마나 떨어지나(대체 불가능성), MI는 모델과 무관한 단변량 신호. 한 지표의 편향을 서로 상쇄. 값이 아니라 순위를 섞어 단위 차이를 없앰 |
| ② 그림자 비교 | 각 피처를 행 순서만 섞은 "그림자 피처"와 SHAP 비교(Boruta) | 우연히 높게 나오는 노이즈 수준을 피처마다 자동으로 기준선으로 삼음 |
| ③ 중복 제거 | 순위 순서대로 보며 Spearman ρ가 0.95 이상인 하위 피처 제외 (413 → 약 312) | 거의 같은 피처 두 개는 중요도를 나눠 가져 둘 다 밀려남. 하나만 남겨야 k개 안에 다양한 정보가 들어옴 |
| ④ k 선정 | k = 5\~150 + 전체를 스윕, 1-SE 규칙 | 아래 |

**왜 k = 50인가 (1-SE 규칙).** 각 k로 상위 k개만 써서 5-fold 점수(macro-F1)를 재고, 최고점에서 1 표준오차를 뺀 기준선을 넘는 가장 작은 k를 골랐습니다.

| k | 40 | **50** | 60 (최고) | 80 | 100 | 150 | 전체 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 점수 | 0.524 | **0.527** | 0.532 | 0.529 | 0.531 | 0.530 | 0.530 |

- 최고점 0.532(k=60), 표준오차 0.0075 → 기준선 0.525. k=40(0.524)은 못 넘고 k=50(0.527)부터 넘습니다.
- 왜 최고점 k가 아닌가: k=50\~전체의 차이는 fold마다 흔들리는 폭보다 작아서 "진짜로 더 좋다"고 말할 수 없습니다. 구분이 안 되면 피처가 적은 쪽이 과적합과 연도 차이에 덜 흔들립니다(Breiman 1984의 1-SE 규칙).
- fold마다 상위 50개가 조금씩 다릅니다. 최종 학습(전체 선박)에는 5개 fold에서 상위에 든 빈도를 1순위로 정렬한 통합 순위를 씁니다.
- 참고로 위치를 뺀 Pool A는 같은 규칙으로 k=307(거의 전부)이 나왔습니다. 위치가 없으면 행동 신호가 약한 피처 여러 개에 얇게 퍼져 있다는 뜻입니다.

### 2.4 r4\_rp가 쓴 상위 50개 (범주별)

### 2.5 지역 사전확률 (`step1_experiments.py`, 10개)

**무엇**: 모항 위치와 주 조업지(이동 시간대 위치의 중앙값) 각각에서 가장 가까운 학습 선박 30척을 찾아, 그 30척의 업종 비율 4개와 평균 거리 1개를 피처로 넣습니다. 2개 기준 × 5 = 10개, 거리는 구면 거리(haversine)입니다.

**왜**: 어촌·항구마다 주력 업종이 다릅니다(지역 어업 구조). 위경도를 그대로 주면 트리가 지도를 상자 모양으로 잘라가며 배워야 하는데, 7천 척으로는 엉성합니다. "이 동네 배들은 자망이 60%"를 직접 알려주면 트리가 한 번의 분기로 쓸 수 있습니다.

**왜 30척인가**: 1척이면 사실상 "바로 옆 배의 정답"이라 개별 선박을 외우는 것에 가깝고 잡음도 큽니다. 30척은 "지역 분포"로 볼 수 있는 크기입니다. 10·100척, 거리 가중, 5km 격자도 시험했지만 모두 ±0.003 안이었습니다(지역 정보 포화).

**누수 방지**: 학습 선박은 자기 자신을 이웃에서 뺀니다. 교차 검증에서는 그 fold의 학습 선박만 이웃으로 씁니다. rfid\_id로 학습 정답을 직접 가져오는 방식은 쓰지 않았습니다.

**효과**: 모든 검증 지표에서 +2\~3%p(cv 0.568 → 0.586), 이번 프로젝트에서 가장 큰 단일 개선입니다.

## 3. 모델

최종 모델은 세 모델(LightGBM, CatBoost, 가설 2단계 계층 모델)이 각각 낸 4클래스 확률을 **똑같은 비중(1/3씩)으로 평균**한 앙상블입니다. "2단계"는 앙상블의 단계가 아니라, 세 구성원 중 하나가 자체적으로 2단계 구조라는 뜻입니다(`step1_experiments.py`의 `fit_core`, 모델 정의는 `train_classifiers.py`).

```
선박 피처 449개
 ├─ ① LightGBM (4클래스)                         → p1
 ├─ ② CatBoost (4클래스)                         → p2
 └─ ③ 가설 계층 모델
        1단계 LightGBM (4클래스)
        2단계 LightGBM (자망 vs 연안복합만)  → p3
확률 = (p1 + p2 + p3) / 3  →  × 클래스 가중(4절)  →  가장 큰 업종
```

### 3.1 왜 트리 부스팅인가

- 표본이 선박 7,372척뿐입니다. 이 규모의 표 데이터에서는 트리 부스팅이 딥러닝보다 강하다는 것이 알려져 있고, 실제로도 그랬습니다(TabM 0.486, TabPFN 0.586 vs 부스팅 앙상블 0.600).
- 바다 기록이 거의 없는 배(약 18%)는 피처 대부분이 빈값입니다. 트리 부스팅은 빈값을 따로 채우지 않고 "빈값이면 어느 쪽으로 보낼지"를 스스로 배웁니다.
- 피처 단위가 제각각(시간, km, 비율, 개수)이어도 정규화가 필요 없고, 치우친 분포·이상치에 강합니다.

### 3.2 LightGBM

**원리**: 그래디언트 부스팅은 작은 결정 트리를 하나씩 추가하며, 새 트리가 지금까지 모델의 오차(손실함수의 기울기)를 줄이는 방향으로 학습합니다. 4클래스에서는 클래스별 점수를 각각 쌓고 softmax로 확률을 만듭니다. LightGBM의 특징은 두 가지입니다.

- **히스토그램 분할**: 연속값을 작은 구간(여기서는 63개)으로 묶어 분할 후보를 줄입니다. 빠르고, 작은 값 차이에 덜 과적합합니다.
- **잎 우선(leaf-wise) 성장**: 층마다 균등하게 키우는 대신, 오차를 가장 많이 줄이는 잎부터 나눕니다. 같은 크기에서 표현력이 크지만 과적합이 쉽기 때문에 `num_leaves`와 `min_child_samples`로 제한합니다.

| 설정 | 값 | 왜? |
| --- | --- | --- |
| 트리 수 / 학습률 | 500 / 0.03 | 작은 학습률로 많이 쌓아 한 트리의 실수가 결과를 좌우하지 않게 |
| `num_leaves` / `min_child_samples` | 31 / 20 | 기본값. 잎 1개에 최소 20척이 있어야 해서 한두 척에 맞춘 규칙을 막음 |
| 행 / 열 샘플링 | 0.8 / 0.7 | 트리마다 일부 선박·피처만 보게 해 트리끼리 덜 비슷하게(분산 감소) |
| L2 규제 / `max_bin` | 1.0 / 63 | 잎 값이 극단으로 가지 않게 / 구간을 거칠게 해서 노이즈 분할 감소 |
| 클래스 가중 | 없음 | 리더보드가 정확도라서. 균형 가중은 소수 클래스를 과하게 예측해 정확도를 떨어뜨림 (cv 0.586 → 0.598, 4절) |

**왜 기본값인가 (Optuna 튜닝을 버린 이유)**: fold 안에서 다시 3-fold로 나눠 튜닝했더니 기본값보다 낮았습니다(0.526 vs 0.538). 약 4.7천 척을 3개로 나누면 튜닝 목표 점수 자체가 잡음이 커서, 최적화가 잡음에 맞춰진 것입니다.

### 3.3 CatBoost

**원리**: 같은 그래디언트 부스팅이지만 두 가지가 다릅니다.

- **대칭(oblivious) 트리**: 같은 깊이의 모든 노드가 같은 분할 조건을 씁니다. 깊이 6이면 조건 6개로 64칸을 나누는 셔입니다. 자유도가 낮아 그 자체로 강한 규제가 되고, 작은 데이터에서 안정적입니다.
- **순서형(ordered) 부스팅**: 보통의 부스팅은 한 선박의 오차를 그 선박을 이미 본 모델로 계산해서 오차를 실제보다 작게 보고, 그만큼 과적합합니다. CatBoost는 선박들을 무작위 순서로 세우고, 각 선박의 오차를 "앞 순서 선박들만으로 만든 모델"로 계산해 이 편향을 줄입니다.

| 설정 | 값 | 왜? |
| --- | --- | --- |
| 깊이 / 학습률 / L2 | 6 / 0.05 / 3 | 기본에 가까운 안정적인 값 |
| 트리 수 | 학습 선박의 15%를 떼어 조기 종료(200회 개선 없으면 멈춤)로 찾은 최적 횟수 × 1.15로 전체 재학습 | 트리 수를 데이터가 정하게 하되, 검증용 15%도 마지막에는 학습에 씀. 데이터가 15% 늘었으니 횟수도 그만큼 |
| 클래스 가중 | 최종에서는 없음 | 아래 SqrtBalanced 참고 |

**왜 넣었나**: 단일 모델 중 가장 안정적이었고(macro 단계 B 0.531), 대칭 트리라는 다른 모양의 모델이라 LightGBM과 틀리는 선박이 다릅니다. 앙상블은 틀리는 지점이 다를수록 효과가 큽니다.

**SqrtBalanced란**: CatBoost의 자동 클래스 가중 옵션입니다. 클래스 c의 가중은 아래와 같습니다.

```latex
w_c^{\text{Balanced}} = \frac{\max_k N_k}{N_c} \qquad w_c^{\text{SqrtBalanced}} = \sqrt{\frac{\max_k N_k}{N_c}}
```

| 업종 | 선박 수 | Balanced | SqrtBalanced |
| --- | --- | --- | --- |
| 연안복합 | 3,650 | 1.0 | 1.0 |
| 자망 | 2,520 | 1.45 | 1.20 |
| 통발 | 1,044 | 3.50 | 1.87 |
| 채낚기 | 158 | 23.1 | 4.81 |

- Balanced는 채낚기 1척을 연안복합 23척처럼 취급해서, 애매한 배를 대량으로 채낚기로 예측했습니다. SqrtBalanced는 가중을 제곱근으로 누그러뜨려 소수 클래스는 챙기되 과보정을 막습니다. macro-F1 단계에서 Balanced 0.456 → SqrtBalanced 0.531로 가장 큰 차이를 만들었습니다.
- **단, 최종 모델에서는 학습 시 가중을 끄고, 예측 후 클래스 가중(4절)으로 대신했습니다.** 리더보드 지표가 정확도(micro-F1)로 확인되면서, 학습 단계에서 소수 클래스를 끌어올리는 것이 오히려 손해였기 때문입니다. 학습은 정직한 확률을 내게 하고, 결정 기준만 따로 맞추는 쪽이 더 통제하기 쉽습니다.

### 3.4 가설 2단계 계층 모델 (`m_hier_hyp`)

**구조**

1. **1단계**: 3.2절과 같은 LightGBM으로 4클래스 확률 p를 냅니다.
2. **2단계**: 자망과 연안복합 선박만으로 "자망인가?"를 푸는 이진 LightGBM을 따로 학습합니다. 입력은 상위 k개에 가설 피처(A\~H, 선박 내 이질성 `_std`)를 최대 30개 더한 것이고, 트리 700개, 열 샘플링 0.5입니다. 출력은 q = P(자망 | 둘 중 하나)입니다.
3. **합치기**: 두 클래스에 배정된 확률의 합은 1단계 값을 유지하고, 그 안에서의 배분만 2단계가 정합니다. 통발·채낚기 확률은 그대로입니다.

```latex
P(\text{자망}) = (p_{\text{자망}} + p_{\text{연안}}) \cdot q \qquad P(\text{연안복합}) = (p_{\text{자망}} + p_{\text{연안}}) \cdot (1 - q)
```

**왜 만들었나**: 가장 큰 오류가 자망↔연안복합 혼동입니다(자망의 약 절반이 연안복합으로 예측됨). 4클래스 모델은 모든 쌍을 한꺼번에 풀어야 하지만, 전문 모델은 두 업종의 경계에만 분할을 씁니다. 자망 = 고정 어구를 펴고 다시 걷는다, 연안복합 = 배가 직접 조작·표류한다는 가설 피처를 여기에 집중시켰습니다.

**솔직한 결과**: 단독으로는 같은 1단계 LightGBM과 차이가 없었습니다(A +0.002, B −0.004). 4클래스 모델이 이미 같은 가설 피처를 쓰고 있어서 더해지는 정보가 없었던 것입니다. 결론은 "가설은 피처로는 유효하고, 모델 구조로는 이득이 없다"입니다. 그래도 자망/연안복합 배분을 다르게 하는 구성원으로 앙상블에 남겨 두었습니다.

현재 `all_rp_no25`에서는 1단계와 2단계 모두 전체 피처를 씁니다.

### 3.5 왜 단순 평균인가

- **스태킹이나 가중 평균을 쓰지 않은 이유**: 선박 7천 척으로 구성원 가중까지 학습하면 그 가중이 다시 과적합됩니다. 실제로 로지스틱 스태킹(cv 0.6087)은 cv는 조금 높았지만 2025 항적 검증(cross\_seen\_adj 0.6660)은 단순 평균(0.6716)보다 낮았습니다.
- **왜 이 세 개인가**: RandomForest(0.511), LogReg(0.394), TabM, TabPFN, MIL, CNN, MiniRocket은 단독 성능이 낮거나, 섞어도 ±0.003 안이었습니다.
- 참고로 ①과 ③의 1단계는 같은 LightGBM입니다. 따라서 실제 비중은 LightGBM 계열 2/3, CatBoost 1/3이고, ③은 자망/연안복합 배분만 달리 하는 변형입니다.

## 4. 후처리: 클래스 가중 보정

평균 확률에 클래스별 가중치를 곱한 뒤 가장 큰 업종을 고릅니다. 현재 가중치는 연안복합 1.35, 자망 1.0, 통발 1.492, 채낚기 1.105입니다(`train_classifiers.fit_class_weights`).

```latex
\hat{y} = \arg\max_c \; w_c \cdot \bar{p}_c
```

### 4.1 방법

1. 교차 검증으로 만든 학습 선박 전체의 OOF 확률(각 선박을 학습에 쓰지 않은 모델의 예측)을 줌비합니다.
2. 가중치를 모두 1로 시작합니다.
3. 한 클래스씩 돌아가며 그 클래스의 가중만 0.30\~3.32 사이 25개 값(로그 간격)으로 바꿔 보고, OOF 정확도가 가장 높은 값을 남깁니다.
4. 3을 3바퀴 반복합니다(좌표 하강법).

### 4.2 왜 필요한가

- **모델 확률의 argmax가 정확도 최적이 아니기 때문입니다.** 세 모델을 평균하면 확률이 가운데로 당겨지고, 클래스마다 그 정도가 다릅니다. 가중치는 클래스 사이의 결정 경계를 옮겨 이를 바로잡습니다.
- **학습과 결정을 분리하기 위해서입니다.** 학습에 클래스 가중을 넣으면 확률 자체가 왜곡되고 트리 구조도 바뀝니다. 학습은 가중 없이 하고 끝에서 결정 기준만 맞추면, 지표가 바뀌어도(macro ↔ micro) 모델을 다시 학습하지 않고 가중치만 다시 맞추면 됩니다.
- **리더보드 지표에 맞추기 위해서입니다.** 처음에는 macro-F1 기준으로 맞췄고, 리더보드가 micro-F1(=정확도)임을 확인한 뒤 정확도 기준으로 바꿨습니다. 같은 모델에서 OOF 정확도가 0.568 → 0.589(같은 OOF로 맞춤), 과적합을 뺀 LOFO 기준으로는 0.586으로 올랐습니다.

### 4.3 가중치 해석

가중치는 상대값만 의미가 있습니다. 자망을 기준으로 보면 연안복합은 1.35배, 통발은 1.49배, 채낚기는 1.11배 더 쉽게 선택됩니다.

값은 재학습할 때마다 바뀌므로 정밀한 값으로 해석하면 안 됩니다. 자망 대비 연안복합은 `select`(1.65배)를 빼면 1.35배로 비슷하지만, 통발과 채낚기는 모델마다 다릅니다.

| 모델 | 연안복합 | 자망 | 통발 | 채낚기 |
| --- | --- | --- | --- | --- |
| `r4_rp` | 1.105 | 0.819 | 1.492 | 1.492 |
| `all_rp` 기존 | 1.221 | 0.905 | 1.221 | 1.221 |
| `all_rp_no25` | 1.35 | 1.0 | 1.492 | 1.105 |
| `select` | 1.492 | 0.905 | 1.35 | 1.35 |

### 4.4 과적합 점검과 솔직한 효과

- 가중치를 OOF로 맞추고 같은 OOF로 채점하면 난관적입니다. 그래서 `cv_adj`는 **한 fold를 뺀 나머지 fold의 OOF로 가중치를 맞추고 뺌 fold에 적용**하는 방식(LOFO)으로 계산했습니다.
- `cross_seen_adj`는 학습 OOF로 맞춘 가중치를 2025 항적 예측에 적용한 값입니다. 다른 데이터에 적용하므로 과적합이 없습니다.

| 단계 | 가중 전 | 가중 후 |
| --- | --- | --- |
| 초기 모델(학습 시 균형 가중 사용), cv | 0.568 | 0.586 |
| `r4_rp`(학습 시 가중 없음), cv | 0.6044 | 0.6032 |
| `r4_rp`, 2025 항적(cross\_seen) | 0.6709 | 0.6716 |
| `all_rp` 기존, cv | 0.6080 | 0.6104 |
| `all_rp_no25`, cv | 0.6066 | 0.6034 |
| `all_rp_no25`, 2025 항적(cross\_seen) | 0.6765 | 0.6752 |
| `select`(조업행태 피처), cv | 0.6047 | 0.6100 |

초기에는 학습 가중이 만든 편향을 바로잡아 효과가 컸습니다. 학습 가중을 끈 뒤로는 cv 기준 효과가 −0.003\~+0.005로 모델마다 부호가 다르고, 오차(±0.006) 안입니다. 현재 모델에서는 cv와 2025 항적 모두 가중 후가 조금 낮습니다. 가중은 점수를 만든 주원인이 아니고, 끄는 편이 나을 수도 있지만 차이가 오차 안이라 아직 정하지 않았습니다. 현재 제출 파일에는 가중이 적용되어 있습니다.

## 5. 검증 방법

모든 실험은 같은 선박 단위 5-fold 분할로 비교했습니다. 판단 기준은 시기에 따라 바뀌었고, 현재 기준은 5.6절입니다. 리더보드는 100척뿐이라 흔들림이 너무 커서 기준으로 쓰지 않습니다.

### 5.1 분할: StratifiedGroupKFold(5)

- **Group = rfid\_id**: 같은 배가 학습과 검증에 동시에 들어가지 않게 합니다. 점수는 "처음 보는 배"에 대한 성능입니다. 시간·하루 단위로 분할하면 같은 배의 다른 날이 양쪽에 들어가 배를 외운 것만으로 점수가 오릅니다.
- **Stratified**: fold마다 업종 비율을 맞춥니다. 채낚기가 158척뿐이라 안 맞추면 fold 간 점수 차이가 커집니다.
- **모든 실험이 같은 fold를 씁니다**(`results/fold_rankings.json`, seed 42). 두 설정의 차이가 fold 운이 아니라 설정 차이에서 나오게 하기 위함입니다.

### 5.2 지표 세 가지

이 절과 5.3절은 Test A 재구성 전의 설명입니다. cross\_seen이 리더보드와 비슷하다는 내용은 지금은 맞지 않고, 현재 역할은 5.6절에 있습니다.

| 지표 | 학습 모델 | 채점 대상 | 흉내 내는 상황 |
| --- | --- | --- | --- |
| cv | fold 모델 (2026 학습 선박 80%) | 그 fold 검증 선박의 2026 항적 | 처음 보는 배, 같은 연도 |
| cross\_unseen | fold 모델 | 그 fold 검증 선박의 **2025** 항적 | 처음 보는 배, 다른 연도 |
| cross\_seen | 학습 선박 전체 | 학습에도 있는 테스트 선박 6,842척의 **2025** 항적 | 학습한 배, 다른 연도 = **리더보드와 가장 비슷한 상황** |

- 테스트에는 정답이 없으므로, 같은 배의 2026 업종을 2025 정답으로 가정했습니다(업종 허가는 해마다 거의 바뀌지 않음). 이 가정으로 정답을 "채점"에만 썼고, 모델 입력으로는 쓰지 않았습니다.
- **왜 cross\_seen인가**: Test A 100척 중 91척이 학습에 있는 배이고, 채점은 2025 항적입니다. cv는 "처음 보는 배"라 리더보드보다 어렵고, 같은 연도라 연도 차이를 못 봅니다. cross\_seen은 그 둘 다 리더보드와 같습니다.
- **왜 cross\_unseen도 보나**: cross\_seen은 학습한 배를 다시 보므로 배를 외우는 모델이 유리합니다. cross\_unseen(0.611)이 cv(0.604)와 비슷하고 cross\_seen(0.672)과의 차이가 제어되어 있다는 것은 모델이 배 ID가 아니라 행동으로 일반화한다는 근거입니다.
- `_adj`는 4절의 클래스 가중을 적용한 값입니다.

### 5.3 채택 기준

재구성 전에는 **cross\_seen\_adj가 +0.005 이상 오르고 cv가 떨어지지 않을 때만 채택**했습니다.

- +0.005는 6,842척 중 약 34척, Test A 로는 약 0.5척에 해당합니다. 이보다 작은 차이는 리더보드에서 나타나지 않습니다.
- 두 지표를 함께 보는 이유: cv만 오르고 cross\_seen이 떨어지면 2026 데이터에만 맞춘 것이고(예: 의사 라벨링, 라벨 잡음 제거), 반대면 우연일 가능성이 큽니다.
- 당시 r4\_rp는 이 기준에 조금 못 미쳤지만(+0.001) 떨어지는 지표가 없고 cv가 +0.005 올라 제출했고, 리더보드에서 3척 더 맞췄습니다.

### 5.4 리더보드를 기준으로 쓰지 않은 이유

- Test A는 100척이라 1척 = 1%p = 총점 0.005입니다.
- 정확도 0.6 근처에서 100척 표본의 표준오차는 약 ±0.05(5척)입니다. cross\_seen(6,842척)의 표준오차는 약 ±0.006입니다.
- 리더보드에 맞춰 고르면 100척의 우연에 맞추게 되고, 비공개 채점이 따로 있다면 떨어질 위험이 큽니다.

### 5.5 누수 방지 점검표

| 항목 | 처리 |
| --- | --- |
| 피처 선정 | fold의 학습 선박으로만 순위·k 계산 |
| 지역 사전확률 | 자기 자신 제외, CV에서는 학습 fold 선박만 이웃 |
| 클래스 가중 | 검증 점수는 LOFO(다른 fold로 맞춘 값) |
| 항구 격자·출어일 유형 | 학습에서 만든 것을 테스트에 고정 적용 |
| 선박 ID | 분할에만 사용. 모델 입력 제외, rfid\_id로 학습 정답을 찾는 방식 미사용 |
| 전처리 규칙 | 라벨과 무관하게 고정 |

| Test B와 학습의 같은 ID | 10척이 겹치지만 연결해 쓰지 않음 |

### 5.6 현재 지표의 역할과 채택 기준 (2026-11-03)

주최 측이 Test A를 **학습에 없는 선박 100척**으로 바꿨고(항적 CSV는 그대로, 제출 양식의 선박 목록만 변경), 팀 규칙도 "분류는 2026으로 학습하고 2026으로 검증한다"로 정했습니다. 공개된 테스트 항적은 학습이 아니라 선택과 검증의 참고로만 볼 수 있고, 2025 정보가 들어간 피처는 쓰지 않습니다.

| 지표 | 재구성 전 | 현재 |
| --- | --- | --- |
| cv (처음 보는 배, 2026) | 보조 | **판단 기준** |
| cv\_adj (가중 적용) | 보조 | 보조. 가중 탐색 격자에 민감 |
| cross\_unseen (처음 보는 배, 2025) | 보조 | 참고 |
| cross\_seen (학습한 배, 2025) | 채택 기준 | 참고 |

- 채택 기준: cv가 표준오차(약 ±0.006)를 넘어 오르고 fold 방향이 대체로 같을 때. 지금까지 이 기준을 넘은 변경은 재구성 이후 없습니다.
- 2025 참고 표본에서는 제출 양식에 들어간 선박을 모두 뺍니다(6,832척).
- 제출 결과: `r4_rp` Test A 0.57, `all_rp` 0.59, 총점은 둘 다 0.69입니다. 2척 차이는 오차(±0.05) 안입니다. `all_rp_no25` 제출 후 표시값은 0.59 / 0.69로 그대로입니다. 이전의 0.62는 배 구성이 달라 직접 비교할 수 없습니다.

### 5.7 왜 리더보드보다 검증 세트가 더 설득력 있나

모델의 실력을 설명하는 근거는 7천 척 규모의 검증 세트이고, 리더보드는 그 검증이 실제로도 맞았는지 확인하는 외부 점검입니다. 순위를 정하는 공식 점수는 여전히 리더보드입니다.

**이유 1. 표본 크기.** 정확도 0.6 근처에서 표본이 작으면 우연만으로 크게 흔들립니다.

| 평가 | 표본 | 표준오차 | 95% 범위 |
| --- | --- | --- | --- |
| 리더보드 Test A | 100척 | ±0.049 | ±0.10 |
| 2026 교차검증 (cv) | 7,372척 | ±0.006 | ±0.011 |
| 2025 처음 보는 배 (cross\_unseen, 참고) | 6,832척 | ±0.006 | ±0.012 |

리더보드 0.59는 "실력이 0.49\~0.69 사이"라는 정도의 정보입니다. 두 모델이 2척 차이 나는 것은 운으로 충분히 설명됩니다.

**이유 2. 표본 구성.** 새 Test A는 바다 기록이 거의 없는 배(6개월간 이동 시간 0, 대부분 기록 1\~2시간)가 25%입니다. 학습 데이터에서는 5%(389척)입니다. 리더보드 점수는 모델보다 "어떤 배가 뽑혔나"에 크게 좌우됩니다.

**검증으로 리더보드를 설명할 수 있습니다.** 교차검증의 그룹별 정확도를 새 Test A 구성비로 섞으면 실제 점수와 거의 같습니다.

```latex
0.25 \times \underbrace{0.52}_{\text{희소 선박}} + 0.75 \times \underbrace{0.61}_{\text{나머지}} \approx 0.59 \quad (\text{실제 } 0.57 \sim 0.59)
```

리더보드가 낮아진 원인은 모델이 아니라 어려운 배의 비중이며, 검증이 실제 성능을 예측한다는 근거입니다. 희소 선박을 따로 처리하는 5가지 방법도 시험했지만 2026·2025 결과가 엇갈려 채택하지 않았습니다(`step8_sparse.py`). 기록이 1\~2시간뿐인 배는 어떤 방법으로도 약 0.52\~0.55입니다.

**검증 세트를 믿을 수 있는 조건과 우리 상태**

| 조건 | 상태 |
| --- | --- |
| 누수가 없을 것 | 충족. 선박 단위 분할, 피처 선정·지역 사전확률·클래스 가중을 모두 fold 안에서 계산 (5.5절) |
| 실제 상황을 닮을 것 | 충족. 처음 보는 배(cv) + 다른 연도(cross\_unseen), 구성비 환산이 리더보드와 일치 |
| 같은 검증 세트로 너무 많이 고르지 않을 것 | 부분 충족. 같은 5-fold로 30개 넘는 설정을 비교해 1등 점수가 약간 부풀려졌을 수 있음. 조업행태 피처의 선별 +0.008이 재학습에서 −0.002가 된 것이 실제 예. 다만 후보 간 차이가 대부분 ±0.005 안이고, 채택한 개선(지역 사전확률, 재방문 간격)은 2026·2025 두 데이터셋에서 같은 방향으로 확인됨 |

**보고 방식**

1. 주 근거: 검증 성능을 신뢰구간과 함께 제시 (cv 0.607 ± 0.011, 7,372척 / cross\_unseen 0.613, 6,832척).
2. 그룹별 성능: 희소 선박 0.52, 일반 선박 0.61로 어디서 틀리는지 설명.
3. 외부 확인: 리더보드 점수를 구성비 환산 예측(0.59)과 비교.
4. 한계 명시: 같은 검증 세트로 여러 설정을 비교했기 때문에 2025 항적으로 한 번 더 확인했다는 점.

### 한계의 원인

- **라벨 자체가 섞여 있습니다.** 연안복합은 한 허가로 여러 어구를 쓰는 업종이라, 자망·통발과 항적이 같은 배가 많습니다. 오류의 대부분이 자망→연안복합, 통발→연안복합입니다.
- **바다 기록이 거의 없는 배가 약 18%입니다**(학습 1,305척, 테스트 1,216척). 이 배들은 행동 피처가 비어 지역 정보로만 맞힐 수 있습니다.
- **1시간 집계와 GPS 지터**로 어구를 넣고 빼는 세부 동작은 많이 지워집니다.

### 얻은 교훈

실제 리더보드를 올린 것은 더 큰 모델이 아니라 도메인 지식에서 나온 피처 두 가지였습니다. "지역마다 주력 업종이 다르다"(지역 사전확률)와 "어구를 놓고 며칠 만에 다시 찾는가"(재방문 간격)입니다.

반대로 조업행태 문서로 만든 피처는 단일 모델 선별에서 오른 +0.008이 앙상블에서 사라졌습니다. 피처 실험은 단일 모델 결과로 판단하지 말고 최종 구성까지 돌려 봐야 합니다.

### 참고: Test B를 비운 이유

사고 선박 판별 AUROC 0.80은 실력처럼 보였지만, 바다 시간 수만으로 0.786이 나오는 활동량 효과였습니다. 활동량을 맞추면 0.52\~0.66으로 떨어집니다. 배마다 사고 시각을 짚는 적중률도 무작위에 가까웠습니다. 사고현황에 선박 ID가 없어 확실히 매칭된 사고가 40건뿐이고, 사고의 절반이 항구 안에서 났습니다. 모의 채점에서는 어떤 탐지기·몇 척을 채워도 빈칸보다 낮아서 비워 두었습니다. 다만 총점 계산은 추정이라 확정된 사실은 아닙니다.
